# Architecture Decision Records

ADRs record important decisions that affect Adhya's architecture and are intended to remain understandable after implementation details change.

## Naming
Use sequential names:

`ADR-0001-short-title.md`

## Status
Use one of: Proposed, Accepted, Superseded, Deprecated.

## Required sections
- Context
- Decision
- Alternatives considered
- Consequences
- Security impact
- Operational impact
- Related issues

## Rules
- Create an ADR when a decision materially affects architecture, interoperability, security, data ownership, deployment or research methodology.
- Do not use ADRs for routine implementation choices.
- Superseding a decision creates a new ADR; do not rewrite history.
